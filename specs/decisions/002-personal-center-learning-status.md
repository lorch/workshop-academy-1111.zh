# DR-002: 个人中心与课程学习状态

## 状态

草案（2026-11-11）。
新增个人中心菜单、区分已学完与未学完、由学员手动标记已学完已经用户明确提出或确认。
其余规则为本次整理的建议方案，尚未作为已接受决策。
本记录补充 [DR-001](001-enrollment-mvp.md) 的报名场景，不替换其报名及观看资格决定。
本次交付为新增需求记录，功能尚未实现。

## 背景

- 学员需要集中查看哪些课程已经学完、哪些课程尚未学完。
- 现有系统提供登录、课程目录、课程管理与限时播放，尚无个人中心及持久化学习状态。
- 报名能力已在 [DR-001](001-enrollment-mvp.md) 中约定，但当前代码尚未实现。
- 当前每门课程对应一个视频，本需求的学习状态以“学员 + 课程”为单位。

## 决策

### 已确认需求

| 编号 | 需求 | 依据 |
| --- | --- | --- |
| D1 | 新增“个人中心”菜单，进入后查看本人的课程学习状态 | 用户本次请求 |
| D2 | 学习状态区分为“已学完”和“未学完” | 用户本次请求 |
| D3 | 学员手动点击“标记已学完”完成状态变更 | 用户明确选择手动标记 |

### 建议的最小交付范围

以下规则构成待审阅的需求方案。

| 维度 | 建议规则 |
| --- | --- |
| 菜单入口 | 登录后在站点顶部导航显示“个人中心”，桌面与窄屏均可访问 |
| 身份边界 | 页面及数据接口仅访问当前登录者本人的课程和学习状态，管理员身份不提供他人学习记录查询能力 |
| 未登录访问 | 访问个人中心页面进入登录页，登录成功返回个人中心；直接请求其数据或标记接口时拒绝访问 |
| 课程范围 | 展示本人当前有效报名的课程，每门课程一条，不混入未报名及已取消报名的课程 |
| 默认状态 | 有效报名课程没有本人的完成记录时显示“未学完”，包括已有报名且没有历史学习数据的课程 |
| 状态筛选 | 默认展示“全部”，可切换“未学完”“已学完”，列表展示所选状态的课程 |
| 列表信息 | 每条展示课程名称、学习状态与进入课程详情的入口 |
| 完成操作 | “未学完”课程显示“标记已学完”按钮，操作成功后显示“已学完” |
| 更新反馈 | 标记成功后立即更新当前列表；在“未学完”筛选下该课程移出列表，在“全部”下保留并更新状态 |
| 重复操作 | 重复或并发标记同一门课程只保留一个已完成结果，不产生重复课程或报错提示 |
| 错误反馈 | 标记保存失败时保留原状态并提示重试，不提前显示“已学完”；列表加载失败时显示错误及重试入口 |
| 空状态 | 无有效报名时显示“暂无已报名课程”及课程目录入口；所选状态没有课程时显示对应空提示 |
| 持久化 | 完成状态关联本人账号，刷新、退出重新登录及服务重启后保持，换账号后不继承前一账号状态 |

### 学习状态规则

- “已学完”表示学员自行确认完成，不代表系统验证了观看时长。
- 点击播放、取得播放地址、拖动进度条或播放结束均不自动改变学习状态。
- 手动标记时，服务端根据当前登录身份验证本人有效报名及课程可用性，不能通过提交他人身份修改其状态。
- 未登录、未报名、报名已取消或课程不可用时拒绝标记，不产生完成记录。
- 标记成功后再次查看个人中心，状态以服务端已保存的结果为准。
- 取消报名后课程退出本次个人中心列表，已有完成记录保留。
- 若后续允许同一课程再次报名，则恢复原有完成状态，不因新报名记录默认重置。
- 本需求不决定是否允许再次报名，仍沿用 [DR-001](001-enrollment-mvp.md) 中 Q4 的待定状态。
- 学习状态不增加或免除观看资格，观看仍遵循 [DR-001](001-enrollment-mvp.md) 的登录、有效报名与课程发布要求。

### 验收场景

以下场景用于审阅建议方案，并在实现时转为系统或集成验证。

| 编号 | Given（前置条件） | When（操作） | Then（预期结果） |
| --- | --- | --- | --- |
| AC1 | 学员已登录 | 使用桌面或窄屏导航 | 能看到并进入“个人中心” |
| AC2 | 访客未登录 | 直接访问个人中心页面 | 进入登录页，登录成功后返回个人中心 |
| AC3 | 学员有两门有效报名课程，一门已标记完成，一门无完成记录 | 进入个人中心并依次切换三个筛选 | “全部”包含两门；“已学完”和“未学完”各只包含对应课程 |
| AC4 | 学员有未报名或已取消报名的课程 | 查看个人中心 | 这些课程不出现在本次列表中 |
| AC5 | 课程处于“未学完”，标记请求成功 | 点击“标记已学完” | 状态保存为“已学完”，当前列表按筛选规则更新 |
| AC6 | 课程处于“未学完” | 播放视频至结束但不手动标记 | 状态仍为“未学完” |
| AC7 | 同一学员对同一课程重复或并发提交标记 | 所有请求完成后刷新 | 仅展示一条课程及一致的“已学完”状态 |
| AC8 | 标记请求保存失败 | 点击“标记已学完” | 保留“未学完”，显示失败提示并允许重试 |
| AC9 | 学员没有有效报名，或所选筛选结果为空 | 查看列表 | 分别显示无报名或对应状态的空提示 |
| AC10 | 列表读取失败 | 进入个人中心 | 显示加载失败及重试入口，不误报为没有课程 |
| AC11 | 课程已经成功标记 | 刷新、重新登录或重启服务后查看 | 同一账号仍显示“已学完” |
| AC12 | 学员 A 与 B 报名同一课程，只有 A 已标记完成 | 从 A 切换为 B 登录 | B 显示自己的“未学完”，读取或修改 A 的记录被拒绝 |
| AC13 | 请求者未登录、未报名、报名已取消或课程不可用 | 直接调用标记接口 | 请求被拒绝且不写入完成状态 |
| AC14 | 学员已完成课程后取消报名 | 再次查看个人中心 | 课程退出列表，完成记录保留 |

### 本轮范围之外

- 自动根据播放结束、累计时长或观看比例判定学完。
- 学习进度百分比、章节级进度、断点续播与学习时长统计。
- 考试、作业、结业证书与管理员学习报表。
- 个人资料编辑、密码管理等其他个人中心功能。

### 后续可选事项

- 是否提供“改为未学完”以撤销误操作，本草案只纳入“未学完 → 已学完”。
- 课程取消发布、删除或更换视频后的历史完成状态展示及重置策略需另行决定，关联 [DR-001](001-enrollment-mvp.md) 的 Q5。
- 交付时间尚未指定，实现前需完成报名能力并将通过审阅的方案固化为行为规约。

## 影响

- 个人中心依赖当前登录身份、报名关系与独立持久化的学习状态，不能仅凭课程播放事件推断完成情况。
- 后续实现涉及导航、个人课程列表与标记操作，页面和直接调用接口均需限制为本人作用域。
- 学习状态的查询与更新不改变已有播放地址的有效性，也不改变视频读取授权方式。
- 如需新增数据库结构，后续实现应追加编号迁移，并保留已有账号、课程和报名数据。
- 本次新增草案并同步规约地图，审阅通过后再建立对应行为与验证规约。
