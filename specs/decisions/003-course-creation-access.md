# DR-003: 新建课程入口的账号权限

## 状态

草案（2026-11-11）。
用户已明确要求“新建课程”按钮仅向登录账号为 `admin` 的用户开放，其余账号置灰。
入口位置、未登录展示与服务端校验细则为本次整理的建议方案。
本次交付为需求记录，功能尚未实现。

## 背景

- 当前“新建课程”入口位于课程管理页的页头和无课程时的空状态区域。
- 当前课程管理页面及接口按管理员角色校验，普通学员无法进入该页面看到按钮。
- 本需求中的 `admin` 指登录账号名 `username`，显示名不参与判断。
- 学员需要看到禁用的新建入口，同时不能通过直接访问地址或接口绕过限制。

## 决策

### 已确认需求

| 编号 | 需求 |
| --- | --- |
| D1 | 仅当前已登录且账号名为 `admin` 的账号可使用“新建课程”按钮 |
| D2 | 其余登录账号看到置灰且不可操作的“新建课程”按钮 |
| D3 | 账号名不为 `admin` 时，即使具有管理员角色也不能使用该按钮 |

### 建议的交互与权限规则

| 场景 | 建议规则 |
| --- | --- |
| 公共入口 | 在课程目录页提供“新建课程”按钮，让普通账号能看到置灰状态；不为展示按钮开放课程管理页及其草稿数据 |
| 可用账号 | 当前会话有效、账号名精确为小写 `admin` 且具有现有管理员角色时，按钮可用并进入新建课程页 |
| 其他登录账号 | 按钮保留显示并置灰，旁边显示“仅 admin 账号可新建课程”；鼠标点击、键盘操作均不能导航或提交 |
| 未登录或会话失效 | 按钮置灰，显示“请使用 admin 账号登录后新建课程” |
| 多处入口 | 课程目录、课程管理页页头及空状态中的新建入口使用一致的可用条件 |
| 无障碍 | 禁用状态可被辅助技术识别，并以文字说明权限限制 |
| 新建页面 | 直接访问 `/admin/courses/new` 时重新校验当前身份；未登录进入登录页，已登录但不满足条件返回 403 |
| 创建接口 | `POST /api/admin/courses` 重新校验当前身份；未登录返回 401，已登录但不满足条件返回 403，拒绝时不新增课程 |
| 身份来源 | 以服务端当前会话关联的账号和角色为准，不采信请求中自报的账号名、显示名或角色 |
| 切换账号 | 页面重新加载后按新账号更新按钮状态；旧页面残留的可用按钮不能绕过服务端对当前身份的校验 |

### 验收场景

以下场景覆盖上述方案，待实现时转为系统或集成验证。

| 编号 | Given（前置条件） | When（操作） | Then（预期结果） |
| --- | --- | --- | --- |
| AC1 | 已登录账号名为 `admin` 且角色为管理员 | 查看并点击“新建课程” | 按钮可用，可以进入表单并创建课程 |
| AC2 | 已登录普通学员账号 | 查看课程目录 | 按钮可见、置灰且有权限说明，点击或键盘操作不打开新建页面 |
| AC3 | 已登录另一管理员账号，账号名不为 `admin` | 查看新建入口或直接请求新建页面及创建接口 | 按钮置灰，直接请求返回 403，不新增课程 |
| AC4 | 账号显示名为 admin，账号名不为 `admin` | 查看新建入口并尝试创建 | 按钮置灰，不能创建课程 |
| AC5 | 访客未登录 | 查看课程目录或直访新建页、创建接口 | 按钮置灰并提示登录，新建页跳转登录，创建接口返回 401 |
| AC6 | 当前显示课程管理页的无课程空状态 | 查看页头及空状态新建入口 | 两处入口遵循相同的账号权限规则 |
| AC7 | admin 打开页面后退出或切换其他账号 | 从旧页面提交创建请求 | 按当前身份拒绝请求，不新增课程 |
| AC8 | 非 admin 账号伪造请求中的账号名或角色 | 直接调用创建接口 | 服务端拒绝创建，课程数量不变 |
| AC9 | 账号名为 `admin` 但已失去管理员角色 | 直接访问新建页或创建接口 | 依照现有角色限制返回 403，不新增课程 |

### 范围边界

- 本需求调整新建课程入口及创建权限，不新增账号或修改账号角色。
- 编辑课程、发布与取消发布等其他操作继续按现有权限规则处理。
- 本需求与 [DR-001](001-enrollment-mvp.md) 的报名及观看资格、[DR-002](002-personal-center-learning-status.md) 的个人学习状态分别管理。

## 影响

- 后续实现需让新建入口对其他账号可见，并保证禁用行为有效。
- 新建页面和创建接口需在现有管理员权限基础上增加账号名限制，不能仅修改按钮样式。
- 后续需在行为规约中覆盖账号名与角色不同、直接请求及会话切换的场景。
- 本需求不涉及数据库结构变更。
